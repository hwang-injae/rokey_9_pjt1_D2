## 0. 먼저 — 드라이버가 실제로 하는 일 (소스 확인)

명령은 `'o'`(열기) `'c'`(닫기) `'i'`(+2.5 N) `'d'`(−2.5 N) `'<0.1mm 정수>'`(폭) 다섯 개뿐인데, **안에서는 전부 같은 일**을 한다 (`OnRobotRGControllerServer.genCommand`):

```
어떤 명령이든 → (목표 힘, 목표 폭, "잡아라") 를 **세트로 다시 전송**
```

→ 🚨 **"힘만 바꾸는 명령"이 없다. 모든 힘 변경은 "다시 잡기"다.**
(RG2 사용자 매뉴얼 §6.2.3 도 같다 — `Target force` 레지스터를 쓴 뒤 `Control=grip` 을 다시 발행해야 적용된다.)

그 밖에 확인된 제약:
- `res.success` 는 **무조건 `True`** 다(`sendCommandCallback`). **응답으로 실패를 알 수 없다.**
- 현재 힘을 읽는 경로가 **없다**. 우리가 기억하는 수밖에 없다.
- 힘 유효 범위는 **3 ~ 40 N**(데이터시트), 편차 **±25 %**. 폭 반복정확도 0.1~0.2 mm + 백래시 0.1~0.3 mm.

## 🔴 D1. 힘 기준을 **0 N 쪽**에서 잡나, **40 N 쪽**에서 잡나

**배경**: 드라이버가 현재 힘을 안 알려 줘서, 우리는 한쪽 끝에 붙여 기준을 잡은 뒤 계단을 세야 한다.

지금 내 코드는 **0 N 쪽**에 붙인다(`'d'` 17회). 그런데 자료를 읽고 두 가지를 알았다:

1. 🚨 **0 N 은 사양 밖이다.** 데이터시트의 유효 범위는 **3 ~ 40 N**. 게다가 드라이버 `'d'` 는 `max(0, …)` 로 **0 까지 내린다**.
2. 🎯 **드라이버는 기동할 때 힘을 이미 40 N(최대)으로 잡아 둔다** — `OnRobotRGControllerServer.py:55` `self.command.rgfr = self.max_force`. 그리고 `'i'` 는 `min(max_force, …)` 로 **40 N 에서 포화**한다.

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **㉠** (지금) | `'d'` × 17 로 **0 N** 에 붙임 | — | 🚨 **사양 밖(0 N)** · 🚨 **쥔 채로 하면 놓친다**(그래서 오늘 `grip_level` 에 "거부" 를 넣어야 했다) · 매번 17회 통신 |
| **㉡** 🟢 민범진 제안 | `'i'` × 17 로 **40 N** 에 붙임 | ✅ 힘이 **올라가기만** 해서 **쥔 채로도 안 놓친다** · ✅ 사양 안(40 N = 최대 정격) · ✅ 드라이버 초기값과 같아 대개 실제 변화 0 · ✅ `grip_level` 의 "거부" 를 없앨 수 있다 | ⚠️ 기준을 잡는 **그 순간 용기가 40 N 을 받는다**(아래 참고) |

**㉡ 의 유일한 걱정과 그에 대한 답**
- 쥔 채로 기준을 잡으면 용기가 잠깐 40 N 을 받는다. 힘 편차 ±25 % 라 실제로는 최대 50 N 일 수 있다.
- 다만 ① 40 N 은 **RG2 최대 정격**이고 핑거팁은 고무다 ② 기준 잡기는 **프로세스당 한 번**이고, 정상 경로(`release()` 뒤)에서는 **빈손일 때** 일어난다 ③ 쥔 채로 기준을 잡는 상황 자체가 **통신 실패 뒤의 예외 경로**다.
- **떨어뜨리는 것보다 잠깐 세게 쥐는 쪽이 낫다**고 본다. 반대면 ㉠ 을 유지하고 `grip_level` 거부도 그대로 두면 된다.

**PM 결정:** ⏳ **검증한 뒤에 정한다**(황인재 9/20 15:50). 오늘 그리퍼 세션은 **지금 코드 그대로**(기준은 0 N 쪽 · 빈손의 `release()` 뒤에서만 — #26·#28) 진행한다 — 시험대가 `release()` 로 시작하므로 놓칠 길이 없다. 세션에서 아래를 재서 기록하면 그 숫자로 바로 정한다:
  1. 브링업 직후 첫 파지의 힘이 정말 40 N 인가(드라이버 초기값)
  2. **빈손**에서 `'i'` × 17(40 N 쪽)과 `'d'` × 17(0 N 쪽)을 각각 했을 때 핑거가 움직이는가 · 걸리는 시간
  3. **그릇(옆면 벽 ≈ 2 mm)·컵을 쥔 채** 40 N 까지 올렸을 때 — 폭 변화 · 용기 변형·자국·소리(힘 편차 ±25 % → 최대 50 N 가정). 3회
  4. (참고) 쥔 채 0 N 쪽으로 내리면 실제로 몇 N 에서 놓치는가 — 용기 아래에 받침을 두고 1회만
  → 3번에서 변형·자국이 없으면 ㉡(40 N 쪽), 있으면 ㉠ 유지 + `grip_level` 거부 그대로.

## 🔴 D2. `HOLD → NORMAL` 로 **되돌릴 것인가**

**배경**: IRD §4 는 "털기·담금은 시작할 때 `HOLD`, **끝날 때 `NORMAL` 로 되돌린다**" 로 정해져 있다. 그런데 위 §0 대로 **모든 힘 변경이 "다시 잡기"** 라서, 방향에 따라 위험이 갈린다.

| 방향 | 무슨 일 | 위험 |
|---|---|---|
| `NORMAL → HOLD` (예 20 → 35 N) | **더 세게** 쥔다 | ✅ 안전 |
| `HOLD → NORMAL` (35 → 20 N) | **덜 세게** 쥔다 | 🚨 **여기서만 미끄러진다** |

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **㉠** (지금 IRD) | 끝날 때 `NORMAL` 로 되돌린다 | 이송 중 용기가 덜 눌린다 | 🚨 **든 채로 힘을 낮추는 유일한 구간**이 생긴다 |
| **㉡** 🟢 민범진 제안 | 끝나도 **`HOLD` 를 유지**한다. 다음 `grip()` 이 어차피 힘을 새로 정한다 | ✅ **위험한 방향을 아예 안 쓴다** · 코드가 단순해진다 | ⚠️ 놓을 때까지 계속 세게 쥔다 → 오래 들고 있으면 용기가 눌릴 수 있다(힘 편차 ±25 % 라 35 N 이 실제 44 N 일 수도) |

🔔 **IRD §4 변경이라 제가 혼자 못 정합니다**(AGENTS §3 규칙 5). ㉡ 이면 `sense.py` 의 `shake`·`dip` 계약 설명과 IRD §4 를 같이 고쳐야 합니다.

## 📌 같이 알아 두실 것 (결정 아님)

- 🟡 **"빈손 = 폭 0 mm" 가 아니다.** 우리가 읽는 폭은 **알루미늄 핑거 사이**(고무 핑거팁 제외 — 드라이버 `OnRobotRGOutput.msg` 주석에 명시)다. 빈손으로 닫으면 **2 × 핑거팁 두께**가 읽힌다. **차이는 여전히 정확히 2 mm 라 그릇·컵·빈손 구분은 된다** — 절대값만 어긋난다. V-05 에서 실제 값을 기록하겠습니다.
- 🚨 **그릇·컵 높이 제한**: RG2 데이터시트 Work Range — 파지 폭이 좁으면 물체 허용 높이 **약 64 mm**, 컵 폭(≈70 mm)에서는 **약 45 mm**. 넘으면 위 §3 의 안전 스위치가 눌린다. **오늘 자로 재서 파지 위치를 정하겠습니다.**
- **힘 편차 ±25 %**(데이터시트). 힘으로 성공 판정하지 않는 현 방식(폭으로 가름)이 맞다.
- **Modbus 동시 연결 1개.** 드라이버를 띄운 채 다른 Modbus 도구를 붙이면 둘 중 하나가 죽는다 → DSN-03 B3 의 B안(XML-RPC 병행)은 위험하다. 덧붙여 **XML-RPC 는 RG2 공식 문서 어디에도 없다** → **B3 는 A안(드라이버)으로 확정 가능**해 보인다.
