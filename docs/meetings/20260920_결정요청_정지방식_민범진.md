## 1. 지금 셀에 있는 정지 3가지 (코드 확인 결과)

| | 무엇 | 누가 누르나 | 무슨 일이 일어나나 | 얼마나 걸리나 |
|---|---|---|---|---|
| **①** | **HMI 정지 버튼** `/flow/stop` | 운영자 (화면) | `flow` 가 깃발만 세운다. **지금 돌고 있는 기능 함수가 끝난 뒤** 다음 호출을 보류하고 `PAUSED` | **함수 하나 분량** — Virtual 측정 **0.6 s**(V-20, 9/20). 🚨 **실기에서는 그 함수가 끝날 때까지** (수 초 ~ 수십 초) |
| **②** | **`Ctrl+C`** → `cobot_common.shutdown()` → `move_stop` | 개발자 (터미널) | 두산 `move_stop` 서비스를 `stop_mode=1`(**`DR_QSTOP` · Stop Category 2**)로 부른다 → 진행 중인 모션을 **중간에 끊으려 시도** | 응답 상한 **2 s**. 🚨 SDD §10: *"움직이는 중의 Ctrl+C는 정지 명령을 **최선으로 시도할 뿐**"* |
| **③** | 🔴 **로봇 E-Stop** (하드웨어 버튼) | 옆에 선 사람 | 컨트롤러가 직접 끊는다. 우리 코드와 무관 | 즉시 |

근거 위치
- ① `src/f2_sense_flow/f2_sense_flow/flow.py` `run_plan()`·`process_one()` · 응답 문구 `flow_node.py`:99 `'현재 동작이 끝나면 정지합니다'` · IRD §6 *"현재 기능 함수가 끝난 뒤 정지 → `PAUSED`(HMI의 소프트 정지 버튼)"*
- ② `src/cobot_common/cobot_common/bootstrap.py`:34 `_STOP_MODE = 1` + `_send_stop()` · 주석에 **"안전 담당(박진용) 확인 대상"** 이라고 적혀 있고 아직 확인 기록이 없다
- ③ SDD §8 위험 대책 *"E-Stop에 손 닿는 사람 1명 상시"* · §7 *"하드웨어 비상정지는 로봇 E-Stop"*

### 🚨 왜 ①이 "즉시" 가 될 수 없나
`cc.move_to(...)` 같은 이동 함수는 **도착할 때까지 돌아오지 않는다**(동기 호출). 그 사이에는 제 코드가 깃발을 볼 기회가 아예 없다.
동작 **중간에** 멈추려면 비동기 이동(`amovej`/`amovel`) + `check_motion` 폴링으로 바꿔야 하고, 그것이 **V-24**(현재 ⏸ 보류·선택 과제)다.

## 3. 결정해 주실 것

### D1. ①을 뭐라고 부를 것인가 (용어 통일) — 🔴 발표·시연에 바로 쓰인다

**배경**: V-20 기록과 제 보고에서 ①을 "소프트 E-STOP" 이라고 쓴 적이 있다. 하지만 SDD §8 위험 대책에는
*"**비상정지 버튼 혼동** — HMI 정지는 **소프트 정지**임을 명시"* 라고 적혀 있다. 두 표현이 섞여 있다.

| 안 | 내용 |
|---|---|
| **(a)** 🟢 민범진 제안 | **"일시 정지(soft pause)"** 로 통일하고, 문서·화면·발표에서 **"E-STOP" 이라는 말을 ①에 절대 쓰지 않는다.** "비상정지" 는 ③만 가리킨다 |
| (b) | "소프트 정지" 로 통일 (현 SDD §8 표현 유지) |
| (c) | 다른 이름 |

> 제가 (a)를 미는 이유: **"E-STOP" 이 들어간 순간 듣는 사람은 "즉시 멈춘다"로 이해한다.** ①은 아니다.

### D3. `Ctrl+C` 의 정지 종류(`DR_QSTOP`)를 **누가 언제 확인할 것인가** — 🚨 안전

**배경**: `bootstrap.py`:34 가 `_STOP_MODE = 1`(**`DR_QSTOP` · Stop Category 2**)로 **하드코딩**되어 있고,
주석에 *"안전 담당(박진용) 확인 대상"* 이라고 적혀 있는데 **아직 확인 기록이 없다.**
드라이버가 주는 선택지는 4가지다:

```
DR_QSTOP_STO(0)  Quick stop (Stop Category 1, STO 없음)
DR_QSTOP(1)      Quick stop (Stop Category 2)      ← 지금 우리 값
DR_SSTO(2)       Soft Stop
DR_HOLD(3)       HOLD stop
```

또 이 값은 **`cobot_common` 주인이 황인재님**이라 **저도 박진용님도 고칠 수 없다**(AGENTS §2 사람별 파일).

| 안 | 내용 |
|---|---|
| **(a)** 🟢 민범진 제안 | **박진용님(안전 담당)이 값의 타당성만 확인**하고 결과를 한 줄 남긴다(코드 변경이 필요하면 황인재님께). 실기 확인은 하지 않는다 — 시간이 없다 |
| (b) | V-24 를 보류에서 풀어 실기로 확인한다 (9/22 이후) |
| (c) | 지금 값 그대로 두고 아무것도 안 한다 → 그러면 **주석의 "확인 대상" 을 지우고 "미확인" 이라고 적어 둔다** |

> 🚨 (c)를 고르시더라도 **주석은 고쳐야** 합니다. "확인 대상" 이라고 적힌 채 두면 다음 사람이 "확인됐겠지" 라고 읽습니다.

### D4. **V-24(동작 중 소프트 정지)를 9/23 동결 전에 할 것인가**

**배경**: V-24 = 비동기 이동(`amovej`/`amovel`) + `check_motion` 폴링으로 **동작 중간에** 멈추게 만드는 것.
현재 **⏸ 보류 · 선택 과제**이고, 하면 ①이 진짜 "1초 안 정지" 가 된다(V-24 완료 기준).

| 안 | 내용 |
|---|---|
| **(a)** 🟢 민범진 제안 | **하지 않는다.** 9/23 동결까지 F2-01·F2-02·UT·L3·L4 가 남았고, `motion.py` 전체를 비동기로 바꾸는 일이라 **모든 기능 함수의 동작이 바뀐다**(AGENTS §3 규칙 9 "9/23 이후 기능 추가 금지" 의 취지에도 맞다). 대신 **①의 한계를 문서·발표에 분명히 적는다** |
| (b) | 시간이 남으면 한다 (현 상태 유지 — 누가·언제가 안 정해져 있다) |
| (c) | 한다 → 담당·날짜를 정해 주세요 |

> 제가 (a)를 미는 이유: 지금 ①이 **함수 하나 분량**까지 줄었다. 시연 시나리오에서 함수 하나는 길어야 십몇 초다.
> 그보다 급하면 **E-Stop 을 쓰는 것이 맞고**, 그게 원래 설계 결정이다(SDD §2: *"정지는 '기능 함수 사이' + 비상정지는 E-Stop — 단순하고 안전"*).
