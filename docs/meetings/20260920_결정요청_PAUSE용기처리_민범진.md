## 1. 무엇이 어긋나 있나

`RACK_FULL`(팔레트 칸 소진)처럼 정책이 `pause` 인 실패로 멈춘 뒤, **사람이 `resume` 을 누르면 그 용기를 어떻게 하는가**에 대해 문서와 코드가 다르다.

| | 말하는 것 | 위치 |
|---|---|---|
| **IRD §8** | `RACK_FULL` → PAUSED + HMI 알림 → **팔레트 교체 후 resume** | `docs/02_인터페이스_IRD.md:140` |
| **SDD §5.1 상태도** | `PAUSED --> (이전 상태): resume` — **하던 자리로 돌아간다** | `docs/03_설계_SDD.md:344` |
| **SDD §6 위험 대책** | 팔레트 만재 → **교체 후 확인 버튼(resume)** | `docs/03_설계_SDD.md:422` |
| 🚨 **내 코드** | `handle_failure` 의 PAUSE 갈래가 `resume` 뒤 **`GO_ON`(= 다음 용기)** 을 돌려준다 → **그 용기를 버린다** | `src/f2_sense_flow/f2_sense_flow/flow.py` `handle_failure` |

문서 셋은 모두 "팔레트를 갈았으니 **그 용기를 마저 적재한다**" 로 읽힌다. 코드는 그 용기를 통째로 버린다.

---

## 2. 그래서 실제로 어떻게 되나 (재현함 — 로봇 없이 mock)

`plan` 그릇 2개 · `policy.RACK_FULL: pause` · `rack_place` 가 `RACK_FULL` 을 내도록 주입:

```
로봇이 집으러 간 순서:  RET_B → SPONGE_BED_B → RET_B → SPONGE_BED_B
                                                  ↑
                                   용기를 손에 든 채 다음 용기를 집으러 간다
rack_place 재시도:      0 회
최종 집계:              plan 완료 — 그릇 0 · 컵 0 · 격리 0
/flow/event:            [] (0 건)
```

### 🚨 문제 ① — 든 채로 다음 용기를 집으러 간다
사람이 팔레트를 갈고 `resume` 을 눌렀는데, 로봇은 **그 용기를 내려놓지 않고** 곧바로 다음 용기의 `pick('RET_B')` 를 실행한다. 그릇을 든 채 다음 그릇을 집으러 내려간다.
"어떤 실패에서도 **툴은 홀더에 반납, 로봇은 안전 높이**"(AGENTS §4)와도 어긋난다.

### 🚨 문제 ② — 그 용기가 기록에서 사라진다
`emit_event` 를 부르는 곳은 세 군데뿐이다 — `DONE`(462) · `SKIPPED`(484) · `ISOLATED`(490). **PAUSE 갈래에는 없다.**
그래서 용기 2개를 집어 무게 재고 세제 칠하고 닦고 헹군 뒤 접었는데 **이벤트 0건 · 그릇 0 · 격리 0** 이다. HMI 의 SQLite `events` 표와 진행률, 시연 집계에서 그 용기가 **통째로 증발한다.**

덧붙여 IRD §7 이 `FlowEvent.result` 로 정의한 네 값 중 **`'ERROR'` 는 저장소 어디에서도 만들어지지 않는다.** 검색하면 `cobot_api/contracts.py:27` 한 곳뿐인데, 거기 `STEPS` 는 줄 끝 주석대로 **`FlowState.step` 의 열거**라 `FlowEvent.result` 와는 다른 필드다.

> 🚨 **②만 고치면 안 된다.** "팔레트를 갈았는데도 그 용기를 `ERROR` 로 버린다" 는 잘못된 동작을 계약으로 굳히게 된다. **①을 어떻게 할지가 먼저다.**

## 3. 결정해 주실 것

### D1. PAUSE 에서 `resume` 하면 그 용기를 **마저 하나, 접나** 🔴

| 안 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **㉠** | **마저 한다** — 실패한 **그 단계부터** 다시 (문서대로) | 정본 문서 3곳과 그대로 맞는다. 사람이 팔레트를 간 보람이 있다. 용기를 안 버린다 | `process_one` 이 **몇 번째 단계였는지 기억했다 되돌아가는** 구조가 필요하다. 13단계 반복문에 인덱스 되감기를 넣어야 한다 |
| **㉡** 🟢 민범진 제안 | **접는다** — 툴 반납 → 용기를 `ISOLATE` 에 놓기 → `HOME` → 다음 용기 | 지금 구조를 크게 안 바꾼다. 필요한 "툴 반납 → ISOLATE → HOME" 은 **이미 9/22 오후 FLOW-01 잔여로 잡혀 있다**(9/20 승인, SDD §7 격리 마무리 순서) — 그걸 이 경로에도 쓰면 된다 | IRD §8 · SDD §5.1 · §6 세 곳을 고쳐야 한다. 사람이 팔레트를 갈아도 그 용기는 격리된다 |

**제가 ㉡ 을 미는 이유**
1. 9/23 기능 동결까지 F2-01·F2-02·UT·L3·L4 가 남았다. ㉠ 은 `process_one` 의 흐름 제어를 바꾸는 일이라 **stop·재시도·정지 경로를 전부 다시 검증**해야 한다(오늘 아침 그 경로를 두 번 고쳤다).
2. ㉡ 에 필요한 동작이 **이미 일정에 있다.** 새로 만드는 게 아니라 부르는 자리를 늘리는 것이다.
3. `RACK_FULL` 은 **시연에서 사실상 안 일어난다** — 그릇 2·컵 2에 팔레트는 그릇 2칸·컵 2칸(9/20 확정)이라 딱 맞는다. 일어나는 건 INT-4b 실패 주입 때뿐이고, 거기서는 "격리했다" 도 정상적인 결과다.
4. 🚨 다만 **`ROBOT_ERROR` 는 ㉡ 을 적용하면 안 된다** — 아래 주의 참고.

**🚨 어느 쪽을 고르든 반드시 같이 지킬 것**
`ROBOT_ERROR` 는 9/20 에 **"그 자리 정지 → PAUSED + 알림, 사람이 복구"**(SDD §7)로 확정했다.
로봇 위치를 모르는 상태이므로 **㉡ 의 "툴 반납 → ISOLATE 로 이송" 을 시키면 안 된다.**
→ 같은 `pause` 정책이라도 `RACK_FULL`(사람이 팔레트만 갈면 되는 상황)과 `ROBOT_ERROR`(사람이 로봇을 복구해야 하는 상황)를 **코드가 갈라서 다뤄야 한다.** 이건 제가 구현으로 처리하겠습니다.

### D2. 그 용기의 `/flow/event` 를 어떻게 남기나

D1 이 정해지면 따라오지만, 값 이름은 확인이 필요하다.

| 안 | 내용 |
|---|---|
| **(a)** 🟢 민범진 제안 | **㉡ 이면 `'ISOLATED'`** 를 쓴다(실제로 격리 구역에 놓으니 뜻이 맞고, 이미 쓰는 값이다). **`ROBOT_ERROR` 로 멈춘 경우만 `'ERROR'`** — 그때는 용기가 로봇 손이나 어딘가에 그대로 있다. `㉠ 이면` 마저 해서 `DONE` 으로 끝나므로 새 값이 필요 없고, 중간에 또 실패하면 기존 정책대로 |
| (b) | 전부 `'ERROR'` 로 통일 |
| (c) | 다른 값 |

그리고 🔔 **`FlowEvent.result` 의 네 값(`DONE`·`ISOLATED`·`ERROR`·`SKIPPED`)을 `cobot_api` 에 상수로 올려 주세요.** 지금 제 코드가 문자열 리터럴을 직접 쓰고 있는데, IRD §2 는 "ID·코드 문자열은 `cobot_api` 상수 사용" 이다. `contracts.py` 는 황인재님 파일이라 제가 못 고칩니다.
