| 일시 | 2026-09-21 오후 |

## 1. 결과 요약

| 확인 | 결과 |
|---|---|
| 현재 힘이 `/onrobot_joint_states` 의 **effort** 로 읽히는가 | ✅ **읽힌다** (단, §3 ③ 조건) |
| 브링업 직후 힘이 **40 N** 인가 | ✅ 40.0 N (**첫 실행에서만** — §3 ②) |
| `'d'` 한 번에 **2.5 N** 인가 | ✅ 40.0 → 37.5 |
| 빈손 영점 | ✅ **10.5 ~ 10.9 mm** |
| 완료 판정을 **폭**으로 하면 | ✅ 0.20 ~ 0.34 s (기존 effort 방식은 매번 10 s 타임아웃) |

→ **PM 께 올린 결정 요청 D1(힘 기준을 0 N 쪽에서 잡나 40 N 쪽에서 잡나)은 철회한다.**
   힘을 **읽을 수 있으므로** 기준을 잡고 계단을 셀 필요가 없다.

## 2. 🔴 설계에 영향을 주는 것 — 빈손이 **0 이 아니다**

```
빈손으로 꽉 닫음  →  10.5 ~ 10.9 mm
```

읽는 폭이 **알루미늄 손가락 사이**라 고무 핑거팁 두께가 빠지지 않는다(드라이버 `OnRobotRGOutput.msg` 주석).

| | 그대로 읽으면 | 영점(10.7)을 빼면 |
|---|---|---|
| 빈손 | 10.7 | **0.0** |
| 그릇(벽 2 mm) | ≈ 12.7 | **2.0** ← 실측 벽 두께와 일치 |
| 컵(상단 75 mm) | ≈ 85.7 | **75.0** ← 실측 지름과 일치 |

🚨 `cell.yaml` 의 `BOWL.grip_width_mm: 2.0` 은 **그대로는 도달 불가능한 값**이다(최소가 10.5).
→ **폭 판정·목표 폭을 모두 "영점을 뺀 값" 기준으로 바꾼다.**
→ 영점은 힘에 따라 0.2~0.4 mm 달라진다(고무가 눌린다) → **판정에 쓸 힘과 같은 힘으로** 잰다.
   이걸 모르면 `NORMAL → HOLD` 전환의 폭 변화를 **미끄러짐으로 오판**한다(V-16 기준이 "폭 변화 ≤ 2 mm").

## 3. 3회 연속 실행에서 드러난 것

3회를 이어서 돌렸더니 1회차만 깨끗했다. **실패가 아니라 시험 방식의 문제**였고, 셋 다 값진 결과다.

### ① 타임아웃이 짧았다 — 3회차 `36.10 mm` 는 무효값

```
1회차  2.19 s → 10.70   ✅
2회차  2.78 s → 10.90   ⚠️ 아슬아슬
3회차  3.00 s → 36.10   ❌ 타임아웃 (닫는 중간을 읽음)
```
**힘이 약할수록 느리게 닫힌다.** probe 의 상한 3 s → **8 s** 로 늘린다.

### ② 🚨 드라이버의 힘 기억이 **프로세스 종료 후에도 남는다**

```
1회차  40 → … → 35   (끝 35)
2회차  35 → … → 30   ← 40 이 아니라 35 에서 이어짐
3회차  30 → … → 25
```
"브링업 직후니 40 N" 은 **첫 실행에서만** 참이다.
→ **힘을 세서 추적하면 안 된다. 읽어서 맞춰야 한다.** (세는 방식이었다면 3회차에 "20 N" 이라 믿는데 실제는 10 N)

### ③ 힘은 **움직이거나 닫혀 있을 때만** 읽힌다

```
1회차  살짝 닫혀 있었음 → 열기 → 움직임 → ✅ 40.0 N
2·3회차 이미 활짝 열림  → 열기 → 안 움직임 → ❌ 안 나옴
```
멈춘 뒤 확인(⑤)은 **3회 모두 ✅**(35 / 30 / 25 N) — 닫혀 있으면 읽힌다.
실제 공정은 **잡은 뒤에** 힘을 쓰므로 문제 없다.

## 4. 부작용 — "잡았다" 신호로는 빈손을 못 가른다

⑤에서 **빈손으로 닫혀 있는데도** 힘이 읽혔다 = 그리퍼의 "잡았다" 비트가 빈손에서도 선다.

→ **폭으로 가르는 우리 설계가 맞다**는 근거다.
→ 강의 노션의 DO/DI 방식(`get_digital_inputs` → 물체 파지 = 3)을 썼다면 **빈손을 성공으로 읽었을 수 있다.**
   발표에서 "왜 강의와 다른 방식이냐" 는 질문이 나오면 이 두 줄로 답한다(폭이 필요하다 · 빈손이 구분된다).

## 5. 전제 — 드라이버가 떠야 한다

`pymodbus` 가 없으면 브링업은 정상인데 **`/dsr01/OnRobotRGControllerServer` 만 0.8 초 만에 죽는다.**
배포본 `setup.py` 가 의존성을 `pymodbustcp` 로 잘못 적어 자동 설치가 안 된다(코드가 쓰는 건 `pymodbus`).

```bash
sudo apt install python3-pymodbus     # 3.6.9 — 우분투 24.04 기본 저장소
ros2 node list | grep -i onrobot      # /dsr01/OnRobotRGControllerServer 가 보여야 정상
```
🚨 `pip install pymodbus` 금지 — 최신은 인자가 `slave=` → `device_id=` 로 바뀌어 드라이버가 또 죽는다.
