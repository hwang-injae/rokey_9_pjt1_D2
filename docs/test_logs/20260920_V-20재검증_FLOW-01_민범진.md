## 1. 무엇을 고쳤나

### ① `flow.py` — stop 을 단계 사이마다 본다 (V-20 결함)
`run_plan()` 은 **용기와 용기 사이** 에서만 `stop` 깃발을 봤고, `process_one()` 의 13단계 반복에서는
보지 않았다. 문서(SDD §5.1 · IRD §6)는 "호출 사이마다" 다.
→ 단계 반복에 `stop` 확인을 넣었다. `resume` 하면 멈춘 **다음** 단계부터 이어 간다.

🚨 **멈출 때 그리퍼에 아무 명령도 보내지 않는다**(황인재 9/20 · SDD §5.1 `dbd1939`).
용기·툴을 든 채 멈추는 구간이 생기는데, 힘을 바꾸면 드라이버가 직전 폭으로 **다시 파지** 하므로
든 채로 명령하면 놓칠 수 있다. 기능 함수가 끝날 때 `HOLD` → `NORMAL` 로 되돌리므로
단계 사이는 **이미 `NORMAL`** 이다.

### ② `gripper.py` — 힘 기준 맞추기를 안전한 자리로 (PM 9/20 · #17 검토 2번)
드라이버가 현재 힘을 안 알려 줘서 **처음 한 번 0 N 까지 내려 기준을 맞춘다**(`'d'` 17회).
그 "처음" 이 `grip_level` 에서 오면 **쥐고 있던 용기를 놓친다**.
→ `_anchor_force()` 로 떼어내고 부를 수 있는 자리를 둘로 제한했다.

| 함수 | 기준이 없을 때 | 왜 |
|---|---|---|
| `release()` | **연 뒤에** 맞춘다 | 손이 빈 게 확실한 유일한 자리 |
| `grip()` | 맞춘다 | 잡으러 가는 길목 = 아직 빈손 |
| `grip_level()` | 🚨 **거부**(RuntimeError) | 이미 쥐고 있다 → 맞추면 떨어뜨린다 |
| `_set_force()` | 🚨 **거부** | 몰래 0 N 으로 내리는 길을 막는다 |

### ③ `sense.py` — `shake`·`dip` 의 `HOLD → NORMAL` 되돌리기를 `try/finally` 로 (주석)
도중에 실패해 `HOLD` 인 채 빠져나가면 ①의 "단계 사이는 이미 NORMAL" 전제가 깨진다.
지금은 본문이 껍데기라 그런 경로가 없다 — F2-01 에서 지킨다.

### ④ `flow.py` — 재개 로그가 거짓말하지 않게
`resume — {끝난 단계} 부터 다시` 는 틀린 말이다(재개 지점이 부르는 자리마다 다르다).
`resume — 이어서 진행한다` 로 바꾸고, 정확한 정보는 멈출 때 찍는다(`… 앞에서 정지`).

멈춘 자리의 로그:
```
stop 요청 — RINSE 앞에서 정지
PAUSED — resume 을 기다린다 · stop 버튼
resume — 이어서 진행한다
plan 완료 — 그릇 2 · 컵 2 · 격리 0
```
`WIPE` 중에 눌러 `WIPE` 만 끝내고 멈췄다. 통과 기준이 "stop 뒤 새 단계 ≤ 1" 인데 **0** 이다.
→ 실기에서 **정지 버튼을 소프트 E-STOP 으로 쓸 수 있다.**

## 4. 같이 올린 것 — `rig_gripper.py` (오늘 오전 그리퍼 세션 도구)

V-05 · V-23 · V-01 을 손으로 30회 받아적지 않게, 재고 판정까지 하는 시험대.

```bash
python3 src/cobot_common/test/rig_gripper.py check                  # 연결만 (안 움직인다)
python3 src/cobot_common/test/rig_gripper.py v05 -n 10              # 빈손, 사람 개입 없음
python3 src/cobot_common/test/rig_gripper.py v23 --kind BOWL -n 10
python3 src/cobot_common/test/rig_gripper.py v01 -n 10              # 빈손 → 그릇 → 컵
```

지키는 것
- 🚨 모든 명령을 **`release()` 로 시작** 한다 — 힘 기준 맞추기가 빈손에서 일어나야 한다(위 ②와 짝)
- **팔을 움직이지 않는다**(`init(robot=False)`) → 두산 드라이버도, 아직 비어 있는 팀 `cell.yaml` 의
  `limits`·`motion` 도 필요 없다
- **Ctrl+C 에 그리퍼 명령을 보내지 않는다** — 쥔 채면 놓는 쪽이 더 위험하다
- 팀 `cell.yaml` 을 읽지 않고 `rig_gripper_config/` 를 쓴다 — `grip_level` 이 읽는 `presets` 의 힘 값이
  팀 파일에서 **비어 있고**, 그 값을 정하는 것이 이 시험(V-16)이기 때문이다(닭-달걀)

V-01 의 산출물은 한석형에게 넘길 `cell.yaml` 값이다:
```
→ 한석형에게 드릴 값 (cell.yaml presets)
     presets.BOWL.width_tol_mm : ?.?   (흔들림 < tol < 간격/2)
     presets.CUP.width_tol_mm  : ?.?
```
범위가 겹치면 숫자를 **지어내지 않고** "제안 불가 — 핑거 패드를 두껍게" 를 낸다(AGENTS §0).
