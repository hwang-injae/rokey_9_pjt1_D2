## 1. 어떻게 돌렸나
- 세 모듈이 아직 골격(로봇을 안 움직임)이라, rig 가 **각 기능 함수 앞에 J1 ±8° 왕복 1회(약 1 s)** 를 끼워 넣고 민범진의 `flow_node.main()` 을 **그대로** 실행했다(모듈 파일은 고치지 않음 — 그 프로세스 안에서만 감쌈). `use_mock` 없음 → `robot=True`, 실제 모듈 3개 import.
- 다른 프로세스의 probe 가 HMI 자리에서 `/flow/start` → 8 s 뒤 `/flow/stop` → `PAUSED` 확인 → `/flow/resume` → `DONE` 까지 재고 기록했다.
- 그 뒤 flow_node 가 **멈춰 있을 때(IDLE) Ctrl+C** → 브링업은 그대로 두고 flow_node·probe 를 다시 실행(2회차).

## 3. 🔴 불일치 — stop 은 용기와 용기 사이에서만 먹는다
- **문서**: SDD §5.1 "메인 스레드는 … 기능 함수를 차례로 부르고, **호출 사이마다 `stop` 깃발을 본다**" · IRD §6 `/flow/stop` "**현재 기능 함수가 끝난 뒤** 정지 → `PAUSED`".
- **코드**: `src/f2_sense_flow/f2_sense_flow/flow.py` 의 `run_plan()` 은 `sig.peek('stop')` 을 **용기 하나를 시작하기 직전에만** 본다. `process_one()` 안의 단계 반복(`for step, mod, fname, args in steps`)에서는 보지 않는다.
- **실측**: `WIPE` 중에 stop → 툴 반납 → 재파지 → `RINSE` → `RACK` → HOME 을 **다 하고** 5.8~6.3 s 뒤에 PAUSED. 이 시험은 함수 1개가 약 1 s 라 6 s 지만, **실기에서는 용기 1개(수십 초)를 끝까지 한 뒤에야 멈춘다.**
- **왜 문제인가**: HMI 의 정지 버튼(소프트 E-STOP)을 눌러도 로봇이 한참 더 움직인다. 시연·UT-FLOW(TC-10)·INT-4 의 "정지 → PAUSED" 기준과 어긋난다.
- **고칠 곳은 민범진의 `flow.py`** 다(F4 는 손대지 않음). 선택지: (a) 문서대로 — `process_one()` 의 단계 사이마다 stop 을 보고 그 자리에서 `PAUSED`, resume 하면 **다음 단계부터** 이어 감 (b) 지금 동작을 유지하고 문서를 "용기 사이"로 고침 — 이 경우 HMI 문구·TC-10·TC-11 기준도 같이 바꿔야 한다. 🚨 (a)에서 주의: 용기를 든 채 멈추는 구간이 생긴다 → 들고 있을 때는 HOLD 가 아니라 NORMAL 파지로 서 있는지, 툴을 든 채 멈춰도 되는지 확인 필요.
- 재현: `rig_v20.py probe` 의 검사 "stop 은 함수 사이에서 먹는다(stop 뒤 새 단계 ≤ 1)" 가 FAIL → 고치면 OK 로 바뀐다.

## 4. 그 밖에 본 것
- `cobot_common.init()` 경고 "설정에 비어 있는 값 3개"는 시험용 설정에 일부러 비워 둔 좌표다(정상).
- Virtual 에는 그리퍼 드라이버가 없다 → 이 시험은 `cc.grip()` 을 부르지 않는다(골격 함수). F1 본문이 들어오면 Virtual 용 가짜 그리퍼가 필요하다(안건 등록됨).
- `prewash_mock.launch.py`(전부 mock, 브링업 없음)도 같은 날 확인: flow_node 기동 · `/flow/state` 2.000 Hz · start 1 ms · 이벤트 4건 · `DONE` 1 s 유지 뒤 `IDLE`.
