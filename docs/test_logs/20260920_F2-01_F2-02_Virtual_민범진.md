## 0. 🚨 이 시험이 확인한 것과 **안 한 것**

Virtual 에는 **힘·무게·접촉이 없고**(AGENTS §5) **그리퍼 드라이버도 없다**(V-20 기록 §4).
그래서 **있는 것(이동)은 진짜 가상 로봇**으로, **없는 것만 가짜**로 바꿔 끼웠다.
실행할 때마다 로그 맨 앞에 경고가 찍힌다 — "다 됐다" 로 읽으면 안 된다.

| | 이 시험 | 실기(V-01·02·05·07·16·23) |
|---|---|---|
| 이동·관절 왕복·Z 하강 | ✅ 확인 | 재확인 |
| 호출 순서·연속 3회 | ✅ 확인 | 재확인 |
| 두산 오류(2.1903 등) | ✅ 없음 | 재확인 |
| **무게 값·잔반 임계** | ❌ 가짜 | 🔴 여기서만 |
| **파지 폭·힘·미끄러짐** | ❌ 가짜 | 🔴 여기서만 |
| **충돌 감지 오작동·안전 스위치** | ❌ | 🔴 여기서만 |

🚨 **좌표는 내가 지어낸 가상 값이다.** 팀 `cell.yaml` 은 아직 비어 있고(한석형 티칭 진행 중),
`WASTE`·`RINSE` 는 `cobot_common/test/config_virtual/` 에도 없었다.
rig 는 **Virtual 이 아니면 실행을 거부**한다(`get_robot_system() != ROBOT_SYSTEM_VIRTUAL` → 종료 2).
f2 값(`amp_deg`·`depth_mm` 등)은 **팀 `params.yaml` 그대로** 쓴다 — 값을 두 곳에 두지 않으려고
실행할 때 임시 폴더에 합친다.

## 2. 🔴 실기에 반영할 측정값 2건

### ① 털기가 설정보다 **약 1.6배 느리다** — V-07 에서 감안할 것

```
설정   4회 × period_s 0.6 s = 2.40 s
실측   한 주기 0.954 s × 4  = 3.82 s
```
로그 시각 차이로 잰 한 주기: `940.85 → 941.80 → 942.76 → 943.71` = **0.954 s** (설정 0.60 s)

**원인은 이미 팀 문서에 있다** — SDD §3.1 `move_joint_rel`: *"실측: 요청보다 약 0.13 s 길다"*.
한 주기는 명령 3번(`period/4` + `period/2` + `period/4`)이므로 **0.13 × 3 ≈ 0.39 s** 가 더해진다.
실측 추가분 **0.354 s** 와 맞는다.

🚨 **V-07 에서 `period_s` 를 정할 때, 적은 값보다 약 0.35 s 느리게 돈다는 것을 전제로 해야 한다.**
털기는 "얼마나 빠르게 흔드나" 가 잔반을 떨어뜨리는 요인이므로 무시할 수 없다.
(이 오버헤드는 명령 횟수에 비례하므로 `cycles` 를 늘려도 주기는 그대로 0.95 s 다)

### ② `move_to` 는 **이미 그 자리에 있어도 안전 높이를 왕복한다**

`shake` 1회 **6.07 s** 중
```
흔들기  3.82 s (63 %)
이동    2.25 s (37 %)   ← 안전 높이로 올라갔다 → 스테이션 상공 → 50 mm 하강
```
설계대로다(`motion.py` — "안전 높이를 거쳐 station 상공으로"). 다만 `leftover_loop` 은
`[weigh → shake]` 를 최대 `max_rounds` 만큼 도므로 **이 왕복이 매 라운드 2번** 일어난다.

**용기 1개에 F2 가 쓰는 시간(Virtual 실측 기반 추정)**

| 경우 | 시간 |
|---|---|
| 잔반 없음 (`weigh` + `dip` + `shake(RINSE)`) | 약 **12 s** |
| 잔반 있음 (위 + `[shake + weigh]` × 2) | 약 **30 s** |

🔔 **시연 시간 계산에 쓸 수 있는 숫자다** — 용기 4개면 F2 만 1~2분. 실기는 `vel_scale 0.3` 이라 더 길어진다.

## 3. 시험대 자체에서 찾은 것 (내 rig 의 문제였다 — 기록해 둔다)

처음 두 번은 `shake 1/3` 만 FAIL 이 났다(복귀오차 19.72° → 7.99° → 0.00°).
**`sense.py` 문제가 아니라 시험대가 잘못 잰 것**이었다.

| 시도 | 어떻게 쟀나 | 오차 | 왜 |
|---|---|---|---|
| 1 | 함수 부르기 직전에 J5 를 잼 | 19.72° | `shake` 안의 `_goto` 가 일으킨 관절 변화까지 같이 쟀다 |
| 2 | `cc.move_to('WASTE')` 로 미리 보냄 | 7.99° | `move_to` 는 **상공까지만** 간다 → 남은 50 mm 하강이 J5 를 또 바꾼다 |
| 3 | `sense._goto('WASTE')` 로 **티칭 자세까지** 미리 보냄 | **0.00°** | ✅ |

→ 교훈: **`move_to` 와 `_goto` 는 다른 자세로 끝난다.** 다른 rig 를 만들 때도 같은 함정이 있다.
