## 2. 바뀐 `gripper.py` 가 실기에서 도는가 (probe)

오늘 오전에 고친 것(힘을 세지 말고 읽기 · 완료를 폭으로 · 안전 스위치 감지)을 본 측정 **전에** 확인했습니다.

| 확인 | 결과 |
|---|---|
| 힘 읽기 | ✅ **40.0 N** (브링업 직후 첫 실행) |
| 2.5 N 계단 | ✅ 40.0 → 37.5 |
| 힘별 영점 | ✅ 10.50 (20 N) / 10.50 (35 N) — **차이 0.00** |
| 잡는 데 걸린 시간 | ✅ **0.20 s** |

🔔 **아침에 본 "영점이 힘에 따라 0.2~0.4 mm 달라진다" 는 틀렸습니다.**
그건 고무가 눌린 것이 아니라 **타임아웃(3 s)에 걸려 닫는 중간을 읽은 것**이었습니다.
상한을 8 s 로 늘리니 **20 N 과 35 N 의 영점이 같습니다.**
→ 결정 E16 의 "영점은 그 종류의 파지 힘으로 잰다" 는 여전히 맞지만, **힘별로 따로 둘 필요는 없습니다.**

그리고 **잡는 시간이 0.20 s** 입니다 — 완료 판정을 폭으로 바꾸기 전에는 매번 10 s 타임아웃이었습니다.

## 4. V-23 — 파지 힘 전환

### 그릇 — ✅ 통과 (10회)

```
최초 파지(NORMAL)  읽은 13.20 · 영점 뺀 폭 2.70 mm
낙하               0 / 10
폭 변화 최대        0.70 mm   (V-16 기준 2.0 이하)
```

🔑 **0.70 은 첫 전환에서만** 났고(13.20 → 12.50), **2~10 회차는 12.50 그대로**였습니다.
→ 미끄러짐이 아니라 **20 N 으로 잡은 것을 35 N 이 제대로 조인 것**입니다.

### 컵 — 🟡 조건부

```
5 N 으로 끝까지 닫기   읽은 68.30 · 영점 뺀 폭 57.80 · 낙하 0/3 · 폭 변화 0.10
   🚨 그래도 육안으로 눌립니다 (민범진 관찰)
```

### 🔴 D2(HOLD → NORMAL 되돌리기) 답

**그릇·컵 모두 힘을 낮출 때 미끄러지지 않았습니다.**

```
그릇  첫 전환 −0.70 → 이후 9회 0.00
컵    첫 전환 −0.10 → 이후 2회 0.00
```

→ **㉠안(IRD 그대로 — 털기 끝나면 NORMAL 로 되돌리기)이 안전해 보입니다.**

## 6. 🔴 컵 — 세 방법을 다 해 봤고, 전부 한쪽을 잃습니다

> **컵을 누르지 않으면서 "잡았는지"도 아는 방법이 없습니다.**

### ① 힘 낮추기 — 최저값에서도 눌림

```
20 N  →  눌림 + 🚨 안전 스위치 작동 (그리퍼 수동 분리로 복구)
15 N  →  눈에 보이게 눌림
 5 N  →  그래도 눌림      ← RG2 로 쓸 수 있는 최저
2.5 N →  데이터시트 유효 범위(3~40 N) 밖
```

🔔 숫자로는 안 잡힙니다 — V-23 이 "폭 변화 0.10 · 낙하 0 · **OK**" 로 통과합니다.
**잡은 뒤의 변화만 재기 때문**이고, 닫히는 **동안** 눌립니다. 육안으로만 보입니다.

### ② 폭 제한(78 mm) — 빈손과 구분 불가 + 힘 전환 깨짐

**빈손으로 같은 명령을 돌려 확인했습니다.**

| | 읽힌 폭 |
|---|---|
| 컵 있음 | **77.90** |
| **빈손** | **77.80** |

→ 차이 **0.10 mm**, 흔들림 **0.20 mm** → **구분 불가.** 그런데 시험은 "낙하 0 · 판정 OK" 로 나왔습니다.

```
 5 N 요청 → 20.0 N 유지
10 N 요청 →  5.0 N 유지  (3회 모두)
```

🚨 **힘 설정이 안 먹습니다.** 드라이버에서 힘 변경은 **"같은 폭으로 다시 잡기"** 인데,
목표 폭에 이미 도달해 있으면 다시 잡을 것이 없어 아무 일도 일어나지 않습니다.

### ③ 힘·신호로 확인 — 빈손과 같은 값

| | 읽힌 힘 |
|---|---|
| 컵을 잡은 상태 | **5.0 N** |
| **빈손** | **5.0 N** |

집게에 **압력 센서가 없습니다** — 드라이버가 **설정한 목표 힘**이 되돌아올 뿐입니다.
"잡았다" 신호도 빈손에서 뜹니다(오전 probe ⑤: 빈손으로 닫혀 있는데 35.0 N).

> 🔔 강의 노션의 DO/DI 방식(`get_digital_inputs` → 물체 파지 = 3)도 같은 한계입니다.
>    그 방식이었다면 **빈손을 파지 성공으로 읽었을 것**입니다 — 폭으로 판정하는 근거가 됩니다.

## 8. 🔧 시험대 결함 2건 (같이 고침 / 미해결)

### ✅ 고침 — 빈손으로도 "판정 OK" 가 났다

`--target-mm`(폭 제한)을 쓰면 목표에 그대로 도달해도 **경고만 하고 통과**했습니다.
9/20 에 같은 종류의 결함(빈손으로도 V-23 통과)을 고쳤는데 **`--target-mm` 을 넣으며 다시 뚫렸습니다.**
→ **목표에 그대로 도달하면 실패(종료 코드 1)** 로 바꿨습니다.

### 🟡 미해결 — `v01` 이 컵을 20 N 으로 잡았다

종류별 힘을 쓰도록 고쳤는데(빈손·그릇 = BOWL 힘 / 컵 = CUP 힘) 실행 로그에 `컵 — 20.0 N` 이 찍혔습니다.
설정에는 `CUP.grip_force_n: 5` 가 들어 있었고, 같은 로직을 따로 돌리면 `CUP → 5` 가 나옵니다.
파일 수정 시각도 실행보다 앞섭니다. **원인을 못 찾았습니다.**
→ 어디서 온 값인지 찍는 진단 로그를 넣었습니다. 다음 실행에서 봅니다.
🚨 **이 버그가 안전 스위치 작동의 직접 원인입니다.**
