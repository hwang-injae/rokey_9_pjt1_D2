# NOTE-01 발표 설명 메모 — ROS 2 노드 구조 · 인터페이스 정의서 (황인재용)

> 노션에 올리는 두 장(① 노드 구조 · ② 인터페이스 정의서)을 **말로 설명할 때** 쓰는 해설. 노션에는 올리지 않아도 된다.

## 1. 30초 요약 — 이것만 말해도 된다

"우리 셀은 **ROS 노드가 2개**입니다. 로봇 PC 의 `flow_node` 가 공정 순서를 돌리고, HMI PC 의 `hmi_bridge` 가 화면을 보여 줍니다.
집기·무게·닦기 같은 기능은 **노드가 아니라 `flow_node` 가 차례로 부르는 파이썬 함수**입니다.
두 노드는 **토픽 2개로 상태를 보내고, 서비스 4개로 버튼을 받습니다.** 액션은 쓰지 않습니다."

## 2. 용어를 한 줄로

| 용어 | 한 줄 설명 | 우리 셀에서 |
|---|---|---|
| 노드 | ROS 에서 통신하는 프로그램 하나 | `flow_node`, `hmi_bridge` |
| 토픽 | 한쪽이 계속 **방송**하고 듣고 싶은 쪽이 듣는 통로 (라디오) | `/flow/state` 초당 2번 상태 방송 · `/flow/event` 용기 하나 끝날 때마다 |
| 서비스 | **요청하면 한 번 대답**하는 통로 (전화) | HMI 버튼 4개 → `/flow/start` 등 |
| 액션 | 오래 걸리는 일을 맡기고 중간 경과를 받는 통로 | 안 씀 — 공정은 flow_node 안에서 돌고 경과는 `/flow/state` 로 |
| 패키지 | 코드를 묶는 폴더 단위 | 8개 (노드가 든 것 2 · 함수 모듈 3 · 라이브러리 2 · 런치 1) |
| DDS · 도메인 | ROS 2 가 PC 사이에 메시지를 나르는 방식 · 방 번호 | `ROS_DOMAIN_ID=60`, 평소 격리 · 통합 때만 `team60` |

## 3. 그림을 짚으며 설명하는 순서 (노드 구조도)

1. **왼쪽 큰 상자 = 로봇 PC(한석형 PC)**, 오른쪽 = HMI PC(내 PC). 두 PC 는 같은 스위치.
2. 왼쪽 위 파란 점선 = **`flow_node` 프로세스 하나**. 안에 노드 2개(`flow_node` 통신 노드 · `flow_node_dsr` 두산 전용 보조 노드)와 **메인 스레드**가 있다.
3. 초록 상자 **메인 스레드**가 공정 순서(집기 → 무게 → 털기 → 안착 → 세제 → 닦기 → 헹굼 → 적재)를 돌며, 그 아래 회색 점선 상자 **F1·F2·F3 함수**를 부른다. 함수들은 **`cobot_common`**(공용 로봇 함수)을 통해서만 로봇을 움직인다.
4. 아래 회색 사각형 = **드라이버 노드**(두산 · 그리퍼). 강사님이 준 것이고 우리는 서비스로 부르기만 한다. 그 아래가 실제 하드웨어(컨트롤러 · RG2).
5. 가운데 노란 타원 = **토픽 2개**(상태 · 이벤트). 로봇 PC 에서 HMI PC 로 간다.
6. 가운데 검은 선 = **서비스 4개**(시작 · 일시 정지 · 재개 · 중단). HMI 버튼이 로봇 PC 로 요청한다.
7. 오른쪽 = `hmi_bridge` → 웹 화면. 화면은 **이 PC 안에서만** 열린다.

## 4. "왜 이렇게 했나" — 받을 질문과 답

**Q. 기능마다 노드를 만들지 않은 이유는?**
처음엔 노드 5개 · 서비스 12개였습니다. 그런데 **서비스 콜백 안에서 두산 API 를 부르면 멈춰 버리는 것**(교착)을 9/18 실험으로 확인했습니다. 두산 API 는 "혼자 위에서 아래로 도는 스크립트"를 전제로 만들어져서, 명령마다 스스로 응답을 기다리기 때문입니다. 그래서 두산 API 가 원하는 방식대로 **한 프로그램이 함수를 차례로 부르는 구조**로 바꿨습니다(결정 DSN-02b). 서비스 12개가 같은 이름의 함수 12개가 됐을 뿐 약속 내용은 같습니다.

**Q. 그럼 4명이 따로 개발할 수 있나요?**
네. 함수의 이름 · 인자 · 반환을 `cobot_api` 한 파일에 약속해 두었고, 물건은 정해진 자리에서만 넘깁니다. 그래서 각자 용기를 손으로 놓고 **자기 함수만 단독 시험**(`rig_f1.py` 등)합니다. flow 는 가짜 함수(`mock`)로, HMI 는 가짜 flow(`fake_state_pub`)로 로봇 없이 먼저 만들었습니다.

**Q. 버튼을 누르면 어떻게 멈추나요? 동작 도중에도 멈추나요?**
버튼 → 서비스 → flow_node 의 통신 스레드가 **깃발만 세웁니다**. 로봇을 움직이는 메인 스레드의 이동 함수가 0.05 초마다 깃발을 보고 로봇에 멈춤(`move_pause`)을 보냅니다. 그래서 **이동 도중에도** 그 자리에서 서고, 재개하면 **하던 이동을 이어서** 갑니다(9/22 실기 — 관절 이동 2/2 확인, 직선 이동은 이어서 확인 중). 터미널 Ctrl+C 도 정지 명령을 보내고 끝납니다(5/5, 0.5 초). 진짜 비상정지는 **로봇 E-Stop** 입니다.

**Q. 콜백에서 로봇을 바로 멈추면 되지 않나요?**
콜백에서 두산 함수를 부르면 앞의 교착이 다시 생깁니다. 그래서 규칙이 "**로봇 함수는 메인 스레드에서만, 콜백은 깃발만**"입니다.

**Q. 실패하면 어떻게 되나요?**
함수는 예외를 던지지 않고 **결과 코드**(`code`)를 돌려줍니다. flow 가 코드마다 정해진 대로 처리합니다 — 잔반이 안 떨어지면 격리 구역으로, 힘 상한·시간 초과는 한 번 다시 해 보고 격리, 놓쳤거나 팔레트가 가득 차면 일시 정지하고 사람을 기다림, 로봇 오류는 그 자리에서 멈추고 사람이 복구. 이 표가 설정 파일(`params.yaml` `flow.policy`)에 있어서 코드를 안 고치고 바꿀 수 있습니다.

**Q. 액션을 안 쓴 이유는?**
액션은 "다른 노드에 오래 걸리는 일을 맡기는" 방식인데, 우리는 긴 일을 **같은 프로세스 안의 함수**로 돌립니다. 진행 상황은 `/flow/state` 로 초당 2번 알리니 액션이 필요 없습니다.

**Q. 비전은?**
과제 조건상 쓰지 않습니다. 판단은 **그리퍼 폭**(쥐었나) · **무게**(잔반) · **힘**(닿았나) · **정해진 위치**로 합니다.

**Q. PC 두 대가 서로 안 보이면?**
평소엔 일부러 격리(남의 로봇에 명령이 가지 않게)해 두고, 통합 때만 두 PC 에서 `team60` 으로 엽니다. 그래도 안 되면 한 PC 에서 둘 다 돌려도 기술적으로 같습니다.

## 5. 인터페이스 정의서 — 말할 포인트

- **토픽 2 · 서비스 4 · 액션 0 · 기능 함수 12** — 이 숫자를 먼저 말한다.
- 메시지는 우리가 만든 **`cobot_msgs` 2개**(`FlowState` · `FlowEvent`), 서비스는 ROS 기본 **`std_srvs/Trigger`**(요청 내용 없이 "해라" · 대답은 성공 여부 + 설명).
- `FlowState` = 화면 한 장에 필요한 것 전부(단계 · 수량 · 소모품 · 마지막 코드). `FlowEvent` = 용기 하나의 기록 한 줄(무게 전후 · 결과 · 시간) → 이력 표 · 성공률 · 사이클 타임.
- ID 와 코드는 **모든 곳에서 같은 대문자 문자열**(`BOWL`, `RACK_B1`, `EMPTY_ZONE` …) — 코드 · 설정 · 메시지 · 화면이 어긋나지 않게.
- 드라이버 인터페이스(두산 · 그리퍼)는 우리가 정의하지 않았고 **`cobot_common` 한 곳에서만** 부른다 → 드라이버가 바뀌어도 한 곳만 고친다.
- 숫자(좌표 · 힘 · 속도 · 횟수)는 코드에 없고 **설정 파일 2개**에 있다.
