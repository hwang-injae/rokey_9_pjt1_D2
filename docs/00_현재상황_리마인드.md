## 2. 시나리오 — 용기 1개가 도는 길

HMI 에서 **시작 1회** → 계획대로 그릇 구역(`RET_B`) → 컵 구역(`RET_C`), HMI 가 받은 개수만큼(시연 = 그릇 2 · 컵 2). 비전은 없다 — 판단은 파지 폭 · 하중 · 힘 · 위치로.

| 단계 | 함수 (주인) | 무엇을 | 🔑 지금 기준 핵심 |
|---|---|---|---|
| **PICK** | `f1.pick(zone, kind)` (한석형) | 반납 구역 고정 자리 집기 | 반납 구역은 **내리막 공급 구조** — 꺼내면 뒤 용기가 같은 자리로 → 구역마다 자리 1개(E9). **그릇**: 폭 판정 `grip_width() − 10.58` 이 `2.15 ± 0.6`, 20 N(E16). **컵**: 78 mm 까지만 닫는 **고정 폭 · 판정 없음**(E19). 🚨 **빈손 `cc.release()` 로 시작** |
| **WEIGH** | `f1.move_to('WEIGH', True, kind)` → `f2.leftover_loop` (민범진) | 무게 → 잔반 ≥ 50 g 이면 잔반통 위 **잔반 버리기**(🔄 E24: 물 털기와 **다른 동작** — 쏟아 내기) → 재측정(계속 남으면 격리) | 판정 = 측정값 − 빈 용기값 — 높이마다 생기는 오차는 더해지는 옵셋이라 **같은 자세의 빈 값을 빼면 지워진다**(9/22 F4 R2: WEIGH z 158 그대로 · 그릇 42.3 g · 흔들림 9.5 g). 🔄 9/21 "0 에 잘림" 의 정체는 하중 API(`get_workpiece_weight`)가 **Fz 의 절댓값**이라서였다(z 158 옵셋 −34 g + 그릇 42 g ≈ +8 g → 부호가 떨어져 튄다) → 무게는 **툴 힘센서 Fz 부호 그대로** 읽어야 한다(민범진 `d4d44bc` · 🟡 main 에는 아직 절댓값 방식 — V-02 전제). 단위 kg → g(PR #64). 🚨 **잔반통은 로봇 뒤** — 저울(앞)↔잔반통(뒤) 사이는 **HOME 경유**(E15) |
| **SEAT** | `f1.place(bed)` — **안착 부분은 박진용**(E22) | 스펀지 홈에 **힘으로 찾아 앉힘** (안 맞으면 Periodic 탐색) | `cc.contact_down` · `cc.periodic_search` |
| **SOAP** | `f1.tool(tool, 'PICK')` (황인재 구현) → `f3.soap(3, kind)` (박진용) | 툴(그릇=수세미 · 컵=솔) 집고 세제 3회 | **세제 수조 없음** — 툴 홀더의 비눗물 컵에서 담근다(E18). SOAP 자세 = 툴 홀더 + `depth_mm` 40(계산값 — depth 를 바꾸면 z 도 같이) |
| **WIPE** | `f3.wipe_bowl` / `f3.wipe_cup` (박진용) → `f1.tool(tool, 'RETURN')` | 안쪽만 닦기 → 툴 반납 | **HOME 에서 시작·끝**(F3 가 직접 복귀 · E17). 그릇: 바닥을 힘으로 찾기(2 N) → 바닥 나선 → 벽면 1.5 N 원호. 컵: 바닥 5 N → `move_periodic`(TOOL z ±15 mm + **6번 관절 ±90°** · 3 s × 5) · 1·4번 관절 감시(1° 넘으면 즉시 정지) |
| **RINSE** | `f1.pick(bed, kind)` → `f2.dip('RINSE', 1)` → `f2.shake('RINSE', 3)` | 재파지 → 헹굼 담금 → 물 털기(E24: 잔반 버리기와 다른 동작) | 물은 없다(모션만). **컵은 HOLD(세게 쥐기)가 안 된다**(E19) — NORMAL 힘으로 버틴다 |
| **RACK** | `f1.rack_place(slot, kind)` → `f1.move_to('HOME')` | 식기세척기 팔레트 칸에 적재 | 그릇 칸: 경유점 → 칸 바로 위 → z 만 하강 → 놓기 → y −25 → z +100 으로 빼기. 🚨 팔레트 → 다른 구역은 필요하면 **HOME 경유**(E15 ④ — 9/21 팔레트 충돌) |

→ 기록(`records.csv` · `/flow/event`) → 다음 용기

### 실패하면 (IRD §8 · `params.yaml flow.policy`)

| 코드 | 정책 | 뜻 |
|---|---|---|
| `EMPTY_ZONE` | next_zone | 구역이 비었다 → 다음 구역 (컵은 E19 로 이 판정이 없다 — 개수로 보장) |
| `LEFTOVER_REMAIN` | isolate | 털어도 잔반이 남는다 → 격리 |
| `GRIP_FAIL` | **pause** | 털기·담금 중 놓침 → 멈추고 **사람이 확인**(E12) |
| `SEAT_FAIL` | isolate | 안착 실패 → 격리 |
| `FORCE_LIMIT` · `TIMEOUT` · `RACK_JAM` · `TOOL_FAIL` | retry:1 → isolate | 후퇴 뒤 한 번 더, 안 되면 격리 |
| `RACK_FULL` | pause | 팔레트가 찼다 → 사람이 비움 |
| `ROBOT_ERROR` | pause | 로봇 이상 → 그 자리 정지. 재개하면 **다음 용기**(그 용기는 ERROR 기록) |

### 정지 · 재개 · 중단 (IRD §6)

- **정지(`/flow/stop`)** = 즉시 일시 정지(이동 도중에도). **재개** = 하던 동작을 이어서. 실패로 멈춘 PAUSE 에서 재개하면 **실패한 그 단계부터 다시**(`ROBOT_ERROR` 만 다음 용기)
- **중단(`/flow/abort`)** = PAUSED 에서만 · `ROBOT_ERROR` 면 거부 · 정리 순서 **HOME → 툴 반납 → 격리 → HOME**(E11) → `ISOLATED`
- **Ctrl+C** = 개발자용 정지(`cc.init` 이 가로채 → `shutdown` 이 move_stop DR_QSTOP). **E-Stop 은 언제나 최우선**

## 3. 구조 — 코드가 어떻게 생겼나

- **노드는 2개뿐**: `flow_node`(PC-A · 로봇 PC — **메인 스레드가 기능 함수를 순서대로 부른다**) · `hmi_bridge`(PC-B — FastAPI + rclpy · 웹 화면은 **그 PC 브라우저에서만** 접속, E10)
- **f1·f2·f3 은 노드가 아니라 함수 모듈**이다. 반환은 `cobot_api.*Result`. 공정상 있을 수 있는 실패는 **예외가 아니라 `Result.fail(code)`** (예외는 로봇 이상일 때만)
- **`cobot_common`** = 공용 로봇 함수(`import cobot_common as cc`) — 이동 `move_to`·`move_rel`·`move_joint_rel` · 멈춤 `pause`·`resume`·`halt`·`clear_halt`·`stop` · 그리퍼 `grip`·`grip_level`·`release`·`grip_width` · 힘 `force_on/off`·`contact_down`·`periodic_search`·`safe_retreat`·`move_periodic`·`joints`·`stop_now` · 무게 `weigh`. **파일마다 주인이 있다**(§4)
- 🚨 **실행 뼈대 규칙(SDD §3.2)**: 로봇 함수는 **메인 스레드에서만** · 콜백은 **깃발 세우기·값 읽기만** · 기능 함수 안에서 `rclpy.init`/`spin`/노드 생성 금지 · `DSR_ROBOT2` 직접 import 금지
- **설정**: `src/cobot_common/config/cell.yaml`(좌표 · 속도 · 힘 상한 · 그리퍼 프리셋) + `params.yaml`(`f1`·`f2`·`f3`·`flow`·`hmi` 절 — **자기 절만** 고친다). 숫자를 코드에 적지 않는다(AGENTS 규칙 6)
- **인터페이스**: `/flow/start`·`stop`·`resume`·`abort`(Trigger) · `/flow/state`(FlowState 2 Hz) · `/flow/event`(FlowEvent 용기마다). ❌ **`/cell/force` · `/cell/gripping` 은 없다**(E21 — 만들지 않는다)
- 실행: `ros2 launch prewash_bringup prewash.launch.py vel_scale:=0.3`(실기 첫 실행) · 가짜로 돌릴 때 `use_mock:="f1,f3"`

## 6. 🚨 안전 — 매번

- 🚨 **로봇을 움직이기 전에 툴·TCP 이름을 확인한다**(9/22 사고 · 황인재 승인) — `ros2 service call /dsr01/dsr_controller2/tcp/get_current_tcp dsr_msgs2/srv/GetCurrentTcp` → `GripperDA_v1` · `ros2 service call /dsr01/dsr_controller2/tool/get_current_tool dsr_msgs2/srv/GetCurrentTool` → `Tool Weight`. 비어 있거나 다르면 **움직이지 말고** 브링업을 끈 뒤 펜던트에서 다시 고른다(ROS 명령으로는 안 된다). 9/22 오전 선택이 풀려(10:54~11:17 사이 · 원인 미확인) **posx 이동이 손끝 208 mm 아래로** 갔고(그릇이 바닥에 닿음) 무게가 1.3 kg 로 고정됐다. 그 시간에 찍은 좌표는 플랜지 값이라 쓰면 안 된다
- 🔌 **실기를 끝낼 때는 연결부터 끊고 랜선을 뽑는다**(9/22 황인재) — ① 돌리던 프로그램 터미널 Ctrl+C → 브링업 터미널 Ctrl+C ② 다 꺼진 것을 확인한 뒤 랜선을 뽑는다(다음 사람에게 넘길 때도). 연결된 채로 랜선부터 뽑지 않는다 — 9/22 툴·TCP 선택 풀림의 원인은 못 찾았지만 연결 도중 끊김을 없애 막는다. 넘겨받은 사람은 꽂고 브링업한 뒤 두 이름부터 확인
- **로봇 위치를 모르면 자동으로 움직이지 않는다** — `MoveIncomplete` · `MotionHalted` · 관절 감시 정지. 힘·순응만 끄고 **사람이 복구**. (힘 상한은 위치를 아니까 설계대로 후퇴)
- 첫 실기는 **vel_scale 0.3** · 손은 **E-Stop** · 로봇 주변을 비운다
- 로봇 **툴 회전 속도 한계 225 °/s** — 넘으면 컨트롤러가 거절(알람 1212)
- 6번 관절 큰 회전·특이점 주의 — 9/21 08:40 케이블 꼬임(원인은 팔꿈치 특이점 J3 = 1.7°)
- **Virtual 결과를 믿지 않는 것**: Move Periodic 회전은 Virtual 에서 rx↔rz 가 뒤바뀐다. 실기에서 TOOL rz = 6번 관절, TOOL rx = 4번 관절
- **그리퍼는 시뮬레이션(가상 로봇)에서 검증되지 않는다**(9/21 팀 보고) — 가상 로봇에는 OnRobot 그리퍼가 없다. 그리퍼가 얽힌 확인(폭 · 힘 전환 · 놓기 · 파지 실패)은 **실기로만** 한다. 가상 로봇으로는 팔 동작·흐름만 본다
- 브링업이 이미 떠 있으면 새로 띄우지 않는다(겹치면 에뮬레이터가 바뀐다) · 끌 때는 내가 띄운 것만
- 그리퍼 안전 스위치가 걸리면 컴퓨트박스 전원을 다시 넣어야 풀린다(RG2 매뉴얼 §6.2.3)

## 8. 작업 규칙 — git · PR · 보고

- **브랜치** `<이름>/<날짜>-<taskID>-<설명>` (예 `beomjin/20260921-V-01-grip-zero`) · 🚨 **main 직접 push 금지**
- **PR 제목** `<타입>(<스코프>): <taskID> <제목>` · 올리기 전에 최신 main 병합 → 자동 시험 → 본문 **"실기 영향" 칸에 실기 여부를 솔직히**(E20)
- PM 이 검토·merge(자동 시험 두 환경) · **merge 뒤 브랜치는 PM 이 정리** — merge 뒤에 이어서 작업했으면 **새 PR** 로
- **남의 파일을 고치지 않는다**(`cobot_common` 파일 주인 · `params.yaml` 자기 절) — 예외는 결정으로만(E22 안착 부분)
- 🧪 **테스트는 단위 기능 먼저, 통합은 그다음**(9/22 황인재) — 기능 코드를 다 짰으면 내 함수만 rig 로 단위 테스트(UT-F1/F2/F3)부터. 한 바퀴 전체 통합 테스트는 일정표의 통합 슬롯(L2 · L3)에서 같이 한다. 혼자 통합 테스트로 로봇을 오래 잡지 않는다 — 로봇은 한 대라 남의 단위 테스트가 밀린다. 로봇은 일정표 로봇 슬롯 순서대로
- 로봇을 움직이는 PR 은 녹화 권장 · 실기 기록은 `docs/test_logs/YYYYMMDD_<taskID>_<내용>_<이름>.md`
