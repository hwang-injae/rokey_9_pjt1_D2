# 제안 — RG2 그리퍼의 폭 읽기·힘 지정 경로 (DSN-03 B3 · V-05 · V-23)

| 항목 | 내용 |
|---|---|
| 제안 | 박진용 (F3 · `cobot_common` 정리·리뷰 · 안전) · 2026-09-19 |
| 관련 | DSN-03 안건 **B3**(그리퍼 현재 폭을 읽는 경로) · V-05(드라이버 연결) · V-23(파지 힘 2단계) · V-01·V-15(폭 판정) · V-18(툴 파지 안정성) |
| 담당 | `motion.py`(`grip`·`grip_level`·`release`) = **한석형**. 이 문서는 선택지를 모은 참고 자료이고 결정은 DSN-03·V-05 에서 한다 |
| 확인 범위 | 강사 배포 드라이버 소스(`ws_dsr/src/onrobot-ros2/onrobot_rg_control`)를 읽고 정리했다. **실기에서는 아직 아무것도 확인하지 않았다** — 🟡 표시는 V-05 에서 확인할 것 |

## 1. 요약
- 우리에게 필요한 것: ① **현재 폭(mm)** — 파지 성공·빈손·두 개 파지 판정(V-01·V-15), 툴이 밀리거나 빠졌는지(V-18) ② **파지 힘을 N 단위로** — NORMAL/HOLD 2단계(V-23).
- 경로는 세 가지다: **A. 강사 드라이버(Modbus)만** · **B. Compute Box XML-RPC 직접** · **C. 둘을 섞기**.
- 제안: **A 로 먼저 V-05 를 해 보고, 힘을 N 으로 정확히 줘야 하거나 폭 환산이 안 맞을 때만 B 를 추가(C)** 한다. B 는 예비안으로 준비해 둔다.

## 2. 강사 드라이버(A)로 되는 것 — 소스에서 확인
`OnRobotRGControllerServer`(실기 브링업 `sodreal` 이 띄움, Modbus TCP → Compute Box 192.168.1.1:502)

| 기능 | 방법 | 단위·비고 |
|---|---|---|
| 닫기·열기 | srv `/onrobot/sendCommand` `command: 'c'` / `'o'` | 닫기는 목표 폭 0 까지(물체에 닿으면 멈춤) |
| **폭 지정** | 같은 srv 에 **숫자 문자열** — 예 `'600'` | **0.1 mm 단위**(600 = 60.0 mm). 최대 폭 초과는 잘린다 |
| 힘 바꾸기 | 같은 srv `'i'` / `'d'` | **2.5 N 씩** 올림·내림(내부 값 0.1 N 단위, RG2 최대 40 N). 절대값 지정 명령은 없다 → 예) 40 N 에서 20 N = `'d'` 8번 |
| 현재 상태 | topic `/onrobot_joint_states` (JointState, 원래 `/joint_states` 를 브링업이 remap) | **관절각(rad)** 과 effort(움직이는 동안 힘/10) 만. 폭(mm)·"잡았음" 신호는 내보내지 않는다 |
| 관절각 ↔ 폭 환산 | srv `/onrobot/pose` (`Pose2D` 의 theta → x) 또는 드라이버의 `jointValueToWidth()` 식 | 드라이버 안에 환산식이 있다 → DSN-03 B3 PM 안(`setup_io` 에서 구독 + 환산)이 이것 |
| 행동 서버 | action `/rg6_controller` (GripperCommand) | 목표 = 관절각. 이름은 rg6 이지만 RG2 에도 뜬다 |

A 의 장점: 연결이 하나(드라이버)라 충돌 걱정이 없고, ROS 안에서 끝나며 RViz 그리퍼도 같이 움직인다.
A 의 한계: 힘을 N 으로 바로 못 준다(2.5 N 계단, 현재 값을 드라이버가 기억) · "잡았음" 신호가 없어 폭으로만 판정 · 환산식이 우리 핑거(패드 두께, fingertip offset)와 맞는지 🟡 V-05 에서 확인.

## 3. Compute Box XML-RPC(B) — 예비안
Compute Box 가 XML-RPC(HTTP 위의 원격 함수 호출, 파이썬 기본 `xmlrpc.client`) 창구를 연다. 🟡 포트(41414)와 아래 함수 이름은 V-05 에서 `cb.system.listMethods()` 로 우리 Compute Box 에 있는지 먼저 확인한다.

```python
import xmlrpc.client
cb = xmlrpc.client.ServerProxy("http://192.168.1.1:41414/")
cb.rg_grip(0, 60.0, 20.0)          # 폭 60 mm · 힘 20 N 으로 잡기 (0 = 그리퍼 번호)
cb.rg_get_width(0)                 # 현재 폭 mm
cb.rg_get_grip_detected(0)         # 잡았는지 True/False
cb.rg_get_busy(0)                  # 움직이는 중인지 (완료 대기 — 타임아웃과 함께)
```

B 의 장점: **폭(mm)·힘(N) 절대값** 지정, **현재 폭 mm**, **잡음 감지**를 바로 준다 → V-23(NORMAL 20 N / HOLD 35 N 같은 값을 그대로), V-18(툴 놓침 감시)에 가장 직접적.
B 의 위험: 🟡 브링업의 Modbus 드라이버와 **같은 Compute Box 에 동시에 붙어도 되는지 모른다** · 🟡 우리 Compute Box 펌웨어에 같은 함수가 있는지(아래 확인 1) · ROS 밖 호출이라 RViz 그리퍼가 안 움직인다 · Virtual 에는 Compute Box 가 없어 **실기 전용**.

## 4. 비교
| | A. 드라이버만 | B. XML-RPC 만 | C. A + B 읽기 |
|---|---|---|---|
| 폭 지정 | ✅ 0.1 mm | ✅ mm | A |
| 힘 지정 | 🟡 2.5 N 계단(상대) | ✅ N 절대 | A(계단) 또는 B |
| 현재 폭 | 🟡 관절각 → 환산 | ✅ mm | **B** |
| 잡음 감지 | ❌ (폭으로 추정) | ✅ | **B** |
| 연결 충돌 | 없음 | 드라이버를 안 띄우면 없음 | 🟡 확인 필요 |
| Virtual | ✅ (가짜 그리퍼 노드, 같은 srv) | ❌ | A 부분만 |
| RViz 그리퍼 | ✅ | ❌ | ✅ |
| 코드 위치 | `motion.py` | `motion.py` | `motion.py` |

## 5. 제안 순서 (V-05 안에서 30분)
1. **A 로 폭 환산 확인** — 빈손·그릇·컵을 쥐고 `/onrobot_joint_states` 관절각 → 폭(환산) 과 자로 잰 폭 비교. 오차 ≤ 2 mm 면 **A 로 폭 판정 OK**.
2. **A 로 힘 계단 확인** — `'d'` 를 몇 번 보내 NORMAL 값으로 내리고 닫기, `'i'` 로 HOLD 값으로 올려 다시 닫기(V-23). 쥔 채 전환 10회 낙하 0 이면 **A 로 V-23 OK**.
3. 1·2 중 하나라도 안 되면 **B 확인** — PC-A 에서 `cb.system.listMethods()` 로 함수 목록 → **브링업(드라이버) 켠 채로** `rg_get_width` 만 읽어 본다(읽기부터, 명령은 나중) → 드라이버 명령이 계속 잘 먹는지 확인.
4. 결과로 DSN-03 B3 의 결정 칸을 채우고(`motion.py` 한 곳에만 구현), F3 는 `motion.py` 의 **현재 폭 읽기 함수**(예: `grip_width()`)를 받아 V-18·닦기 중 툴 놓침 감시에 쓴다.

## 6. F3 가 필요한 것 (요청)
- 닦는 동안(3~5 N) 툴이 밀리거나 빠졌는지 알기 위해 **현재 폭(mm)을 읽는 공용 함수** 하나 — 경로가 A 든 B 든 `motion.py` 에 있으면 된다. 반복 루프 안(메인 스레드)에서 짧은 주기로 읽는다(별도 감시 스레드는 쓰지 않는다 — SDD §3.2).
- 판정 기준(예: 쥔 직후 폭 대비 ±2 mm 벗어나면 `TOOL_FAIL`)은 V-18 에서 정한다.
