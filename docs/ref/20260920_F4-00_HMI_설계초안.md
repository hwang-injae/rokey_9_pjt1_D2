## 1. 구조
```
[PC-A] flow_node ──/flow/state 2 Hz · /flow/event──▶ [PC-B] hmi_bridge (프로세스 1개, :8000)
           ▲                                            ├─ rclpy 스레드: 구독 2 · Trigger 클라이언트 3  (콜백은 값 저장·큐에 넣기만)
           └──────/flow/start·stop·resume (Trigger)─────┤  FastAPI(uvicorn): REST · WebSocket · 정적 파일
                                                        ├─ SQLite prewash.db: events · state_log
                                                        └─ 브라우저(노트북·태블릿): 화면 1장
```
- rclpy 는 **별도 스레드**에서 spin, uvicorn 이벤트 루프와 섞지 않는다. ROS 콜백 → `asyncio` 큐 → WebSocket 브로드캐스트.
- 서비스 호출은 `call_async` + 상한 1 s. 응답이 없으면 `{ok:false, message:"flow 응답 없음"}` (요청 스레드를 막지 않는다).
- 설정은 `params.yaml` 의 `hmi` 절(`port` · `state_rate_hz` · `disconnect_after_s` · `db_path`). hmi_bridge 는 두산 API 를 쓰지 않으므로 `cobot_common.init()` 을 부르지 않고 `cobot_common.config.load()` 만 쓴다(PC-B 에 ws_dsr 불필요).

### 🟡 결정 1 — 화면을 무엇으로 만드나
| | A. **Next.js**(정적 내보내기 `out/` 을 FastAPI 가 서빙) | B. `static/index.html` 한 장(지금 문서) |
|---|---|---|
| 장점 | 컴포넌트로 나눠 화면을 빨리 키운다(구역·팔레트·이력·그래프) · 시연 화면 완성도 | 설치 없음 · 빌드 없음 · 파일 1개 |
| 비용 | Node 20.9+ 필요(**이 PC 는 v18.19 → 업그레이드**) · `npm run build` 한 단계 · `node_modules` 가 colcon 에 잡히지 않게 `COLCON_IGNORE` + `.gitignore` 예외 | 화면이 커지면 JS 한 파일이 길어진다 |
| 실행 | 둘 다 **프로세스 1개**(`ros2 run f4_hmi hmi_bridge`) · REST/WS 계약 같음 | |

제안: **A**(9/18 황인재 결정) — 단, **F4-01·02(브리지·버튼·WS)는 화면과 무관하게 먼저** 만들고 확인은 B 수준의 시험 페이지 1장으로 한다. Node 업그레이드가 막히면 그 시험 페이지를 키워 B 로 간다(계약이 같아 버리는 코드가 없다).

## 2. REST · WebSocket 계약 (IRD §6 그대로, JSON 모양만 정함)
| 호출 | 응답 |
|---|---|
| `POST /api/start` · `/api/stop` · `/api/resume` | `{"ok": true, "message": "시작합니다", "latency_ms": 3}` — flow 의 Trigger 응답을 **그대로** 전달. 버튼 활성 조건은 화면이 판단(§3) |
| `GET /api/state` | `{"connected": true, "age_s": 0.2, "state": {FlowState 필드 그대로}, "derived": {…§4}, "plan": {…params.yaml flow.plan·rack_order}}` |
| `GET /api/history?limit=50` | `[{"id":1, "received_at":"…", FlowEvent 필드 그대로}, …]` 최근 것부터 |
| `WS /ws/state` | 서버 → 브라우저만. `{"type":"state", …GET /api/state 와 같은 몸통}`(수신마다 = 2 Hz) · `{"type":"event", …}`(1건마다) · `{"type":"conn","connected":false}`(`disconnect_after_s` 넘게 state 가 없을 때) |

## 3. 화면 1장 (시연에서 청중이 볼 것 우선 · 글자 크게)
```
┌ PreWash-Cell ─────────── ● ROS 연결 0.2 s 전 ── [MOCK] ─────────  [ 정지 (소프트) ]  ← 항상 보임 · 붉은색 ┐
│ [ 시작 ] [ 재개 ]     단계  ○PICK ─ ○WEIGH ─ ●SHAKE ─ ○SEAT ─ ○SOAP ─ ○WIPE ─ ○RINSE ─ ○RACK      BOWL · RET_B │
├──────────────────────────────┬───────────────────────────────┬──────────────────────────────────────────────┤
│ 반납 구역                     │ 팔레트 (그릇 2 · 컵 4)          │ 수량          그릇 1/2   컵 0/2   격리 0       │
│  RET_B [■][□]  처리 중        │  B1[■] B2[□]                   │ 소모품        수세미 ▓▓░░ 4/20  세제 ▓░░ 12/60 │
│  RET_C [□][□]  대기           │  C1[□] C2[□] C3[□] C4[□]       │ 사이클 타임   최근 41 s · 평균 43 s            │
├──────────────────────────────┴───────────────────────────────┴──────────────────────────────────────────────┤
│ ⚠ 알람   SEAT_FAIL → 격리 (14:02:11)        ← 오류(붉은색)·경고(주황) 우선, 최근 5건                          │
│ 이력     시각 · 종류 · 구역→칸 · 시도 · 무게 전/후 · 결과 · 코드 · 소요     ← SQLite, 최근 20건               │
└──────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```
| 버튼 | 활성 조건 (SDD §6) |
|---|---|
| 시작 | 연결됨 + `step` ∈ {IDLE, DONE} |
| 정지(소프트) | 연결됨이면 **항상**. "현재 기능 함수가 끝난 뒤 멈춘다 — 급하면 로봇 E-Stop" 문구를 버튼 아래에 |
| 재개 | 연결됨 + `step` ∈ {PAUSED, ERROR}. `RACK_FULL`·격리 구역 만재는 알람 문구로 "교체·비움 후 재개"를 안내(별도 확인 버튼 없이 재개로 통일) |
| 연결 끊김 | `/flow/state` 가 `disconnect_after_s`(2 s) 넘게 없으면 점이 빨강 + 버튼 3개 비활성 |
| **`ROBOT_ERROR`** | 9/20 확정(SDD §7): 그 자리 정지 → PAUSED, **사람이 복구**. 화면은 붉은 알람 띠에 **"운영자 복구 필요 — ① 로봇·주변 확인 ② 필요하면 `release_force.py` ③ flow_node 재시작 또는 재개"** 를 크게 띄운다. 두산 `DR_Error` 뒤에는 flow 프로세스가 명령을 못 보내므로 **재개가 안 먹을 수 있다** → 재개를 눌러 1 s 안에 응답이 없으면 "flow_node 를 다시 띄우세요"로 문구를 바꾼다. HMI 는 안내만 하고 복구 동작은 하지 않는다 |

## 5. 9/20 실측 — `ros2 launch prewash_bringup prewash_mock.launch.py hmi:=false`
- 런치가 flow_node(전부 mock, `robot=False`)를 실제로 띄운다. `/flow/state` **2.000 Hz**, `/flow/start` 응답 **1 ms**.
- start 1회 → `FlowEvent` 4건(BOWL×2 → RACK_B1·B2, CUP×2 → RACK_C1·C2) → `DONE` 1 s 유지(`flow.done_hold_s`) → `IDLE`. 수량·소모품 값은 IDLE 로 돌아가도 남는다(다음 start 에 초기화).
- 🔔 **mock 은 함수가 즉시 끝나서 PICK~RACK 단계가 화면에 한 번도 안 잡힌다**(2 Hz 사이에 전부 끝남). → 화면 개발·INT-4 에는 ① `fake_state_pub`(시나리오 yaml) ② mock flow 에 시험 설정 `flow.step_delay_s: 0.5`(`PREWASH_CONFIG_DIR`) 둘 다 쓴다.
- mock 의 `FlowEvent` 는 `attempts=0 · weight 0→0 · duration 0.00` 이다 → 이력·KPI 표의 모양 확인은 `fake_state_pub` 로.

## 6. SQLite (`prewash.db`, 경로는 `hmi.db_path` 상대경로)
- `events(id INTEGER PK, received_at TEXT, stamp REAL, kind, zone_id, rack_slot, attempts INTEGER, weight_before_g REAL, weight_after_g REAL, result, code, duration_s REAL, force_log_path)` — `/flow/event` 1건 = 1행.
- `state_log(id, received_at, step, kind, zone_id, done_bowl, done_cup, isolated, last_code)` — 1 Hz 샘플. F4-05 KPI 는 `events` 만으로 계산(성공률·격리율·사이클 타임 평균/편차·탐색 시도 평균).
